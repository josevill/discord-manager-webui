## TL;DR

- **The core IaC promise — "apply twice = no-op" — was broken in five places** (overwrites, `@everyone`, auto-mod, welcome/onboarding, guild icons). All P0 items have since landed.
- **`npm test` was a footgun**: it ran live E2E whenever `.env` has credentials (this repo's does). Default test runs now exclude `tests/e2e`.
- **The riskiest modules (`diff.ts`, `execute.ts`) are excluded from the coverage gate**, and there is no git repo, no CI, and no lint setup.
- **Stickers were in the schema and in `export` but never reconciled** — now reconciled (see checked P0 item).

## Background and problem

The pipeline (validate → fetch → diff → execute) is sound, the WebUI is usable, and 68 unit/integration tests pass. But a full read of the engine (`src/reconcile/diff.ts`, `execute.ts`, `src/state/export.ts`) surfaced concrete defects:

- `overwritesDiffer` flags any live overwrite whose role is not in config (e.g. integration roles). Discord's PATCH is merge, not replace, so the "fix" never lands and every plan shows a channel update forever.
- `diffAutoMod`, `diffWelcomeAndOnboarding`, and the guild icon/banner/splash branch emit UPDATE unconditionally, without comparing against live state.
- `roleFieldsDiffer` compares `@everyone` color/hoist/mentionable, but `buildRolePayload(role, true)` never sends them → perpetual diff with a payload that cannot fix it.
- `channelFieldsDiffer` never compares `position` → UI drag-reorder is silently ignored for existing channels.
- Channel prune matching double-guards on name, so a same-name channel in an unmanaged category is never pruned.
- `watch` contains a dead ternary: `dryRun: !options.auto && !options.yes ? false : false` (always `false`).
- `loadAssetDataUri` has no `http(s):` handling, so any URL-valued image (including every emoji `export` produces) crashes apply with ENOENT.
- `~/.discord-manager/state/` is written by apply/export/UI but read by nothing.

## Goals and non-goals

**Goals**

1. `apply` is idempotent: second run against an unchanged config produces zero non-SKIP actions.
2. `export` output is re-applicable without manual edits (round-trip property).
3. `npm test` never touches the live Discord API; live E2E is explicit and allowlist-gated.
4. The two riskiest modules sit under the coverage gate.
5. The repo is version-controlled, linted, and has CI.

**Non-goals**

- Multi-guild, multi-user, or hosted deployment (local single-guild tool by design).
- OAuth or any auth on the WebUI (127.0.0.1 companion app; see Risks).
- Automatic revert of out-of-band drift (gateway stays advisory in v1).
- SQLite or a state store (JSONL backups + audit + name-based identity stay).

## Risks and open questions

- **Overwrite-delete semantics change what apply does** — emitting zeroed overwrites will actually delete overwrites for config-defined roles that users may have forgotten about. Mitigation: keep it behind the existing confirm flow (deletes still require `--yes`/confirm), and call it out in the P0 item's release note. (confidence: high that current behavior is a permanent-diff bug; medium that users never relied on the "extra overwrite stays" accident)
- **Channel batch reorder vs. per-channel PATCH** — batch PUT rewrites all positions at once; a mid-run failure can leave ordering partially applied. Acceptable for a local tool with backups; noted for the P0 item's test plan.
- **CI host is GitHub Actions** (resolved in P4) — `.github/workflows/ci.yml`: push/PR gate + manual/nightly secrets-gated E2E. If a different host is preferred later, the job mapping is 1:1.
- **E2E allowlist currently defaults to allow** — `E2E_ALLOW_GUILD_ID` unset means "any guild". Recommend inverting: require it for `test:e2e`.
- **WebUI stays unauthenticated on localhost** — acceptable per design (local companion, no OAuth); re-decide only if the bind host ever moves off 127.0.0.1.
